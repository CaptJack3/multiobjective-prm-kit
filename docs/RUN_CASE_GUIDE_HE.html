1 איזה קובץ פותחים?

בשרת שלכם, פתחו בעורך טקסט את הקובץ הזה:

run_experiment.py

בראש הקובץ עורכים רק את CASE_ID ואת בלוק SETTINGS. קוד ההרצה שמתחתיהם כבר קורא לפונקציה. מרחב חיפוש הקירות מוגדר בתוך SETTINGS, באמצעות מספר קירות, מיקומים, מידות וזוויות.

מחשב חדש? התקנה חד־פעמית

צריך את כל חבילת המשתמשים, ולא רק את קובץ Python. חלצו את ארכיון ההפצה, היכנסו לתיקייה המכילה את pyproject.toml, והריצו ב־Linux או WSL עם Python 3.10 ומעלה (נבדק ב־3.11):

python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[robot]'

בשרת הקיים אפשר להשתמש בסביבת Python המוכנה באמצעות הפקודות בשלב 3. קובץ ה־HTML הזה הוא מדריך בלבד: הוא עצמאי ואפשר לפתוח אותו גם ב־Windows; ההרצות מתבצעות בטרמינל.

2 בוחרים תרחיש ומעתיקים הגדרות

בחרו דוגמה. החליפו בקובץ את כל בלוק CASE_ID + SETTINGS בקטע המוצג, והשאירו את יתר הקובץ כפי שהוא. הנתיבים היחסיים בדוגמאות הם ביחס לתיקייה שבה נמצא run_experiment.py.

התחלה קטנה: ארבע סביבות

שני קירות, שני מיקומים לכל קיר. זהו מרחב החיפוש הקטן שמופיע בקובץ; מתאימה לווידוא שהכול עובד לפני הגדלת הניסוי.

4 סביבות · 4 בניות PRM · 8 חיפושים 
CASE_ID = "wall_grid"
SETTINGS = dict(
    profile="mounted_ur5e",
    wall_count=2, grid_points=2,
    offset_range=(-0.2, 0.2),
    widths=[0.6], heights=[0.9], thicknesses=[0.08],
    yaw_offsets=[0], max_environments=4,
    n=[24], k=[6], epsilons=[0.0, 0.05],
    num_queries=1, seed=7, query_k=12, workers=1,
)

שני האפסילונים משתמשים באותו גרף ובאותן עלויות עבור כל סביבה ושאילתה. N=24 הוא ניסוי בדיקה קטן.

שם תיקיית התוצאות המומלץ לדוגמה: runs/first_wall_grid. הפקודות בשלב 3 מתעדכנות לפי הבחירה.

widths

num_queriesמספר משימות תכנון עצמאיות. לכל משימה התחלה ויעד אחד או כמה יעדים חלופיים. אינו מספר מסלולי Pareto.
seed / seedsseed קובע את יצירת הסביבות ובנק השאילתות, וגם את seed התכנון כברירת מחדל. seeds=[7,8] חוזר על התכנון באותן סביבות ומשימות עם seeds שונים.

מחשבון: כמה הרצות יהיו? ✕

מחשבון נפרד להמחשה של wall_grid עם אותן רשימות אפשרויות לכל הקירות. הוא לא עורך את הקובץ ולא משתנה עם בחירת הדוגמה. הזינו מספר ערכים שונים בכל רשימה; עבור טווח הזזה יחיד השתמשו במיקום אחד. לקירות עם הגדרות שונות השתמשו ב־--plan.

4סביבות בתקציב
4בניות PRM
8חיפושי מסלול

environments = min(budget, (positions × widths × heights × thicknesses × yaws) ** walls)
PRMs = environments × queries × len(N) × len(K) × len(seeds)
searches = PRMs × len(epsilons)

כל ערך N משולב עם כל ערך K ועם כל אפסילון — לא מצמדים רשימות לפי מיקום. המספרים הם תוכנית ההרצה, ואינם מבטיחים שכל משימה תקפה או שתימצא לה דרך.

3 שומרים, בודקים ומריצים

שמרו את הקובץ. הריצו את הפקודות הבאות בטרמינל — כולן מאותה תיקיית הפצה. בחרו את סביבת העבודה:

יש להתאים את /path/to לנתיב תיקיית ההפצה שלכם. נדרשת התקנה חד־פעמית ב־.venv.

cd /path/to/multiobjective-prm-kit-0.4.0

א. בודקים את היקף הניסוי

.venv/bin/python run_experiment.py --plan --output runs/first_wall_grid

--plan מציג מספר סביבות, שאילתות, בניות גרף וחיפושים; הוא לא בונה PRM ולא כותב תוצאות. זו בדיקת תוכנית, לא בדיקת התנגשות או הוכחת היתכנות.

ב. מפעילים את הניסוי

.venv/bin/python run_experiment.py --output runs/first_wall_grid

המערכת מייצרת סביבות ובנק שאילתות, בונה PRM עם בדיקות התנגשות, מחשבת עלויות ומריצה חיפוש לכל אפסילון. בסוף מודפס הנתיב לדוח.

הריצה נקטעה? שיניתי הגדרות? איך ממשיכים?

להמשך עם אותם קלטים, קוד ותלויות, הוסיפו --resume לאותה פקודה:

.venv/bin/python run_experiment.py --output runs/first_wall_grid --resume

אם שיניתם הגדרות, בחרו תיקיית תוצאות חדשה, למשל --output runs/revision_2. גם להרצה חדשה של אותה דוגמה בחרו שם חדש. בלי --output, הקובץ משתמש ב־runs/<CASE_ID>.

4 איפה התוצאות, ומה בודקים?

בדוגמה שנבחרה, פתחו בדפדפן את runs/first_wall_grid/report.html. הדוח מאפשר לבחור קבוצת N/K/אפסילון/seed, לסנן לפי שאילתה וסטטוס, להשוות סביבות ולעבור לדוח של הרצה בודדת.

your_output_folder/
  report.html                  # Study dashboard
  results.csv                  # One row per planning run
  study_summary.json           # Machine-readable summary
  queries.json                 # Reusable query bank
  environments/env_00000/scene.json
  configs/run_0000000.yaml      # Generated automatically
  runs/run_0000000/             # Individual run + paths
לציפוף: בחרו סביבה מהדוח, עברו לדוגמת ״ציפוף סביבה שנשמרה״ והעבירו גם את scene.json שלה וגם את queries.json. כך שומרים על אותה סביבה ואותן משימות ומשנים את N/K.
איך מפרשים הצלחה, כישלון ודירוג?
  • complete: החיפוש הסתיים עם תוצאות; no_path_in_roadmap: לא נמצאה דרך בגרף הנוכחי. זה אינו מוכיח שאין דרך בסביבה.
  • invalid_query: המשימה אינה תקפה בסביבה הזו. partial או failed: עיינו בפרטי ההרצה; התוצאה אינה שקולה להרצה שהסתיימה.
  • הדירוג מופרד לכל צירוף N/K/אפסילון/seed. נכללות סביבות שכל שאילתותיהן הוערכו עד לסיום ולפחות אחת מהן נפתרה; קודם מועדף מספר משימות פתורות גדול יותר, ואז ציון ממוצע על המשימות שנפתרו.
  • מספר מסלולי Pareto אינו מספר השאילתות ואינו מדד אוטומטי לגיוון גאומטרי. סיום הניסוי אינו אומר שנמצא מסלול לכל שאילתה.
התוצאות בשרת — איך מורידים ל־Windows?

הורידו את כל תיקיית התוצאות כדי שגם הקישורים לדוחות ולמסלולים יפעלו. התאימו DOMAIN, USER, HOST ואת /path/to לשרת שלכם. הריצו במחשב Windows שלכם:

scp -r "DOMAIN\USER@HOST:/path/to/multiobjective-prm-kit-0.4.0/runs/first_wall_grid" "C:\Users\Master\Downloads"

אחר כך פתחו C:\Users\Master\Downloads\first_wall_grid\report.html. אם בחרתם תיקיית פלט אחרת, התאימו את הנתיב. בניגוד לתוצאות, למדריך הזה מספיק להוריד את קובץ ה־HTML היחיד.

אחרי החיפוש: אימות ובחירת מסלולים

בקובץ ההרצה המקורי של גרסה 0.4 מוגדרים גם verification ו־selection. אם החלפתם את כל SETTINGS בדוגמה קצרה מהמדריך, הוסיפו את השורות הבאות בתוך המילון כדי להפעיל אותם:

verification=dict(enabled=True, backend="coal_mesh", scope="all",
                  min_clearance_m=0.005),
selection=dict(only_verified=True, max_per_query=7),
render=dict(enabled=False),

ייפתח מסלול חדש לקריאת התוצאות: explorer/explore.html בתוך תיקיית הפלט. בו רואים שלוש הקרנות Pareto מקושרות, מסננים לפי סטטוס אימות ובוחרים מסלולים להורדה כ־selected_paths.json. בדיקת Mesh מדוגמת נקראת discrete_verified; היא אינה הוכחת בטיחות רציפה.

אפשר להפעיל מאוחר יותר prmkit verify RUN, prmkit select RUN, prmkit export RUN --selection selected_paths.json או prmkit render RUN --selection selected_paths.json בסביבה שבה החבילה מותקנת. הרינדור הוא סרטון Mesh ב־CPU; ל־Isaac אפשר לייצא USD. אין חיפוש מחדש בשלבים האלה.

כשרוצים לשלוט ביותר דברים

קריאה ישירה לפונקציה run_case בקוד שלי

אפשר ליצור קובץ Python משלכם בתיקיית ההפצה. אין צורך ב־run_experiment.py אם קוראים ישירות לפונקציה:

from pathlib import Path
from prmkit import run_case

ROOT = Path(__file__).resolve().parent

if __name__ == "__main__":
    result = run_case(
        "wall_grid", profile="mounted_ur5e",
        wall_count=2, grid_points=2,
        n=[24], k=[6], epsilons=[0, 0.05],
        num_queries=1, max_environments=4,
        input_dir=ROOT, output=ROOT / "runs/my_api_study",
        dry_run=True,
    )
    print(result)

הריצו את הקובץ באותה סביבת Python. תחילה dry_run=True מחזיר את התוכנית; כדי לבצע, שנו ל־False. לאחר הרצה התוצאה מכילה בין השאר result["report"] ו־result["complete"]. שמרו את בלוק __main__ גם אם בהמשך תגדילו את מספר ה־workers.

התחלה ויעד משלי, או בנק שאילתות קבוע

ב־SETTINGS, הוסיפו queries="runs/first_wall_grid/queries.json" כדי לשחזר משימות מריצה קודמת. השמיטו את num_queries כדי להשתמש בכל הבנק; אם הוא מוגדר, הוא חייב להתאים למספר המשימות שבבנק.

למשימה משלכם, queries=[{"start": [...], "goal": [...]}] מקבל וקטורי מפרקים מספריים בסדר ה־URDF: רדיאנים למפרקים סיבוביים, לא מיקום XYZ. החליפו את סימוני ... בערכים שלכם. אפשר גם קובץ JSON או NPZ.

ללא בנק מפורש, משימות התבנית משמשות ראשונות. אם מבקשים עוד שאילתות, מדגמים מצבי קצה ללא התנגשות בסביבה הראשונה, ושומרים את אותו בנק לכל ההשוואות. אין הבטחה למסלול בין המצבים; סביבה אחרת יכולה להפוך משימה לבלתי תקפה, והיא תסומן כך ולא תידגם מחדש.

שינוי מטריקות ודירוג הסביבות

הוסיפו ל־SETTINGS את הפרמטרים הבאים. כאן שומרים את אורך מסלול הכלי, ומשנים את קנס הקרבה למכשולים:

metrics=[
    "ee_length",
    {"name": "risk", "kind": "clearance",
     "threshold": 0.15, "power": 3, "scope": "world"},
],
rank_by="best.risk",
rank_direction="min",

metrics מגדיר עלויות למסלולים; rank_by בוחר את ציון ההשוואה בין הסביבות. threshold הוא סף קנס הקרבה במטרים, ולא סף איסור התנגשות. בטיחות מוגדרת בנפרד, למשל validation={"margin": 0.01}.

מטריקות מובנות נוספות: joint_length; וכן visibility, שדורשת גם הגדרת מצלמה. לעלות חדשה לגמרי אפשר קובץ Python חיצוני — אין צורך לערוך את ליבת התכנון.

דוגמה מלאה למטריקה חדשה

צרו לצד run_experiment.py קובץ בשם custom_metric.py:

import numpy as np

def elevation_exposure(samples, parameters):
    floor = parameters.get("floor_m", 0.2)
    penalty = np.maximum(0.0, samples.ee[:, 2] - floor)
    return float(np.trapezoid(penalty, x=samples.t)
                 * samples.joint_length)

וב־SETTINGS השתמשו למשל ב־:

metrics=[
    "ee_length",
    {"name": "elevation",
     "plugin": "custom_metric.py:elevation_exposure",
     "parameters": {"floor_m": 0.25}, "symmetric": True},
],
rank_by="best.elevation",

הפונקציה מחזירה עלות קשת סופית ולא שלילית, שמצטברת לאורך המסלול ואינה תלויה בהיסטוריית החיפוש. כל מטריקות המסלול ממוזערות. הגדירו symmetric=True רק כשעלות הקשת זהה גם בכיוון ההפוך.

סביבה שיצרתי ב־Isaac Sim

תחילה מייבאים את קובץ ה־USD של הסביבה בעזרת היבואן. בדוגמה הפקודות מופעלות מתיקיית ההפצה לאחר התקנת החבילה בסביבה הפעילה:

python -m pip install '.[robot,usd]'
prmkit import-usd my_scene.usd --output imported

אחר כך בוחרים CASE_ID="fixed_environment" וב־SETTINGS מגדירים environment="imported/scene.json", N/K ואפסילונים. אל תגדירו יחד איתו wall_count או walls. השתמשו במשימות המתאימות לסביבה שלכם.

היבוא מיועד לגאומטריית התנגשות סטטית נתמכת; יש לשמור גם את קובצי הרשתות. אם הסצנה כוללת רובוט, יש להחריג אותו בייבוא; יש להתאים יחידות ומסגרת בסיס, ולהגדיר רובוט ומשימות במפורש. בזמן התכנון החישובים נעשים במנוע הגאומטרי של החבילה, ללא הרצת סימולציית Isaac.

רובוט אחר או ניסוי קיים

אפשר להוסיף base_experiment="my_project/experiment.yaml" ולרשת הגדרת רובוט, מצלמה, משימות ומטריקות. ב־fixed_environment, אם לא מספקים סביבה או קירות חדשים, נשמרת סביבת הניסוי הבסיסי. N/K/אפסילונים נלקחים מארגומנטי run_case.

אפשר גם להעביר robot כקובץ הגדרה או מילון, יחד עם שאילתות מתאימות. החלפת רובוט דורשת URDF וגאומטריית התנגשות, מסגרת כלי, גבולות ומשקלי מפרקים ומדיניות זוגות התנגשות. אין זיהוי אוטומטי של כל אלה מתוך סצנת Isaac.

המימוש המובנה תומך בבסיס קבוע ובמפרקים סיבוביים או קוויים חסומים, עם קואורדינטה אחת לכל מפרק. בסיס צף או מרחב מצבים אחר דורשים הרחבה בקוד.

מה המערכת עושה כיום, ומה חשוב לדעת על ההיקף?
  • ב־Grid נבדקים צירופים; ב־Random נדגמים ערכים מהטווחים או מהרשימות. זה אינו חיפוש אדפטיבי שלומד מהתוצאות, ואילוצי חפיפה בין קירות אינם מוסקים אוטומטית.
  • שינוי אפסילון בלבד משתמש שוב בגרף ובעלויות מאומתים. שינוי N, K, שאילתה, seed או סביבה בונה גרף נוסף; ״ציפוף״ אינו הרחבה הדרגתית של הגרף הקודם.
  • search={"timeout_s": 120} מגביל כל חיפוש מסלול בנפרד, לא את בניית הגרף או את הניסוי כולו. אפסילון 0 וגרפים גדולים עשויים להיות יקרים.
  • קובצי ההפצה מופרדים מקוד המחקר המקורי. ההגדרות וה־YAML שנוצרים אוטומטית נשמרים בתיקיית התוצאות לצורך שחזור.
