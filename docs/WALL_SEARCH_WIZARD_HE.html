PRM KIT · מדריך מעשי ללא Isaac

בונים חיפוש במרחב הקירות

משנים קירות וטווחים, מקבלים קובצי הגדרות מוכנים, ומריצים חיפוש מקצה לקצה. בכל שלב מופיע בדיוק איזה קובץ ליצור ואיפה לשמור אותו.

שלב 1 מתוך 6

יוצרים תיקיית עבודה חדשה

הדוגמה משתמשת ברובוט UR5e ללא אביזרים, עם משימת התחלה–יעד מוכנה. הקירות נוצרים מקופסאות JSON; אין צורך בסביבה מוכנה, ב־Isaac, ב־USD או ב־GPU.

איפה עובדים? המדריך נפתח בכל דפדפן, גם ב־Windows. את פקודות התכנון מריצים בטרמינל Linux — למשל בשרת המחקר או ב־WSL — שבו מותקנת חבילת PRM Kit. המדריך מכין קבצים; החישובים עצמם רצים בטרמינל.
התקנה ראשונה — אם prmkit עדיין אינו מותקן

צריך את תיקיית user_distribution המלאה, הכוללת pyproject.toml ו־src/. פתחו בה טרמינל, עם Python 3.10 ומעלה, והריצו:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[robot]'

התקנת תלויות דורשת גישה לאינטרנט. בחלון טרמינל חדש יש להפעיל שוב את אותה סביבה. אם החבילה כבר מותקנת, הפעילו את סביבת Python שבה הותקנה.

מתוך תיקיית ההפצה, בסביבת Python הפעילה, הריצו:

prmkit init wall_study --template ur5e
cd wall_study

נוצרת תיקיית wall_study עם נכסי הרובוט. בשלבים הבאים נחליף את קובץ הניסוי של התבנית וניצור שני קבצים נוספים. מכאן כל פקודות התכנון רצות מתוך wall_study.

wall_study/
├── assets/             ← נוצר באמצעות init; משאירים בתיקייה
├── walls.json          ← ניצור בשלב 2
├── experiment.yaml     ← נחליף בתוכן משלב 3
└── space.yaml          ← ניצור בשלב 4: הגדרת החיפוש

אם wall_study כבר קיימת, השתמשו בתיקייה חדשה או המשיכו בפרויקט שכבר הכנתם. init דורש יעד ריק. נכסי E4 שהועתקו עם התבנית אינם הסביבה של המדריך; הניסוי שנייצר מפנה ל־walls.json.

שלב 2 מתוך 6

מגדירים אילו קירות קיימים

צרו קובץ: wall_study/walls.json — זהו תיאור של סביבה אחת בסיסית.

אפשר להתחיל בלי לשנות דבר. לכל קיר מגדירים מרכז ומידות במטרים, ביחס לבסיס הרובוט. הדוגמה כוללת קירות זקופים ללא סיבוב; אין רצפה או מכשולים נוספים.

מבט מלמעלה · XY

הנקודה היא בסיס הרובוט. זהו ציור של הקירות בלבד; בדיקות התנגשות עם הרובוט נעשות בהרצה.

איך מרכז ומידות הופכים לקיר?

position_m: [x, y, z] הוא מרכז הקופסה; dimensions_m: [dx, dy, dz] הן מידותיה המלאות. בקיר A: עובי X=0.08, רוחב Y=0.6, גובה Z=0.9. מרכז Z=0.45 מעמיד את תחתיתו בגובה 0.

הספירה ב־objects מתחילה מ־0: קיר A הוא 0, קיר B הוא 1 וכן הלאה. הוספת פרמטר לחיפוש אינה מוסיפה קיר — את הקיר עצמו מוסיפים כאן.

הצגת התוכן המלא והורדת walls.json
walls.json


שמרו את הקובץ בתיקיית העבודה, לא בתיקיית assets. אם יוצרים בעורך טקסט, השתמשו ב־UTF-8 ושימו לב שלא נוספת סיומת .txt.






שלב 3 מתוך 6
מגדירים מה מריצים בכל סביבה


פתחו: wall_study/experiment.yaml — והחליפו את תוכן התבנית בתוכן המלא שלמטה.


זהו הניסוי הקבוע: אותו רובוט, אותה משימה ואותן הגדרות בכל הסביבות. השורה environment: walls.json מחברת אותו לקירות מהשלב הקודם.










אלה ערכי התחלה קטנים לבדיקת התהליך. epsilon: 0 מבקש חיפוש Exact על הגרף שנבנה. מספר הדגימות אינו מבטיח שיימצא מסלול.


משימה, עלויות ודיוק — אפשר לערוך כאן

התחלה ויעד הם 6 זוויות מפרקים ברדיאנים, בסדר ה־URDF, ולא XYZ של הכלי. prmkit check experiment.yaml מציג את סדר המפרקים. שמרו את המשימה המוכנה להרצה הראשונה.














עלות clearance היא קנס מצטבר על קרבה; ערך קטן עדיף. היא נפרדת ממרווח ההתנגשות הקשיח. המדריך אינו מוסיף מצלמה או מדד נראות. אפשר להוסיף מטריקות אחרות בקובץ הניסוי, בהתאם לממשק החבילה.




הצגת התוכן המלא והורדת experiment.yaml
experiment.yaml


החלפת התוכן מיועדת לפרויקט החדש מהשלב הראשון. אם זה ניסוי שכבר התאמתם, שמרו את הגדרותיו לפני ההחלפה. הרובוט כאן נטען ישירות מנכסי UR5e, ללא החומרה הנלווית של תבנית המחקר.






שלב 4 מתוך 6
מגדירים את מרחב החיפוש


צרו קובץ: wall_study/space.yaml — כאן מחליטים אילו שדות משתנים, בין אילו ערכים ואיך מדרגים.


כל שורה היא משתנה אחד. לדוגמה: 3 מיקומים לקיר A × שלושה לקיר B × שלושה לקיר C = 27 סביבות מועמדות. בכל מועמד מורכבת סביבה אחרת ומורץ הניסוי המלא.









מה משתנה בין הסביבות?












מטריקות המסלול מוגדרות ב־experiment.yaml; rank כאן בוחר איך להשוות סביבות לפי המסלולים שהוחזרו. רק מועמדים שהושלמו עם מסלולים נכנסים לדירוג. מספר מסלולים תלוי גם ב־N/K ובאפסילון.




space.yaml




תצוגה של מועמד מה־Grid






הציור אינו מריץ PRM או בדיקות התנגשות. שינוי גובה אינו נראה במבט מלמעלה.




איך קוראים שדה כמו environment.objects.0.position_m.0?

environment = הסביבה שנטענה; objects.0 = קיר A; position_m.0 = מרכז X. הסיומות 1 ו־2 מציינות Y ו־Z. dimensions_m משנה את המידות. הוספת קיר נעשית בקובץ הקירות; כאן רק משנים שדות של עצם קיים.


למשל, כדי לשנות גם את רוחב Y של קיר A, הוסיפו משתנה עם קיר A, מידת Y וערכים 0.4, 0.8. יחד עם שלושת משתני המיקום המקוריים מתקבלים 54 צירופים. כפתור ״תקציב לכל הצירופים״ יעדכן את התקציב.




גובה, אילוצים ושילובים גדולים

שינוי מידה מתבצע סביב מרכז הקיר. אם משנים גובה בלבד, תחתית הקיר משתנה. כדי לשמור תחתית Z=0, אפשר לערוך ידנית את space.yaml ולחפש על environment.objects.0 עם רשימת הגדרות קיר מלאות, הכוללות גובה ומרכז מתואמים.


אפשר להוסיף ידנית constraints להשוואות בין שדות וערכים, למשל סינון רוחב גדול מדי. אין בדיקת חפיפה אוטומטית בין קירות. אילוץ שמסנן מועמד עדיין צורך מקום בתקציב.


Grid בתקציב קטן סורק רק את תחילת הצירופים, לפי סדר המשתנים והערכים; הוא אינו דוגם אותם. Random דוגם מתוך הטווחים ואינו אופטימיזציה אדפטיבית. תקרת המחולל כאן היא מיליון מועמדים, כדי למנוע יצירת תקציב עצום בטעות; זו אינה מגבלת PRM Kit.








שלב 5 מתוך 6
שומרים ומריצים E2E


    

  1. שמרו את שלושת הקבצים באותה תיקייה. אפשר להוריד אותם יחד ולחלץ ישירות לתיקיית wall_study שנוצרה בשלב הראשון. יש לשמור את תיקיית assets ולבחור בהחלפת experiment.yaml של התבנית החדשה.

    

    ה־ZIP כולל הגדרות בלבד; הוא משתמש בחבילה ובנכסי הרובוט שכבר הכנתם באמצעות init. אם הדפדפן ב־Windows וההרצה בשרת, העבירו את הקבצים גם לשרת — הורדה למחשב שלכם אינה מעדכנת אותו.
    

    העברת ה־ZIP מהמחשב שלי לשרת המחקר
    החליפו DOMAIN, USER, HOST ואת /path/to בפרטי השרת שלכם. בטרמינל של Windows, לאחר ההורדה (הנתיב מניח שיצרתם את הפרויקט במיקום שבשלב 1):
    scp "C:\Users\Master\Downloads\wall_search_configs.zip" "DOMAIN\USER@HOST:/path/to/multiobjective-prm-kit-0.4.0/wall_study/"
    ואז בטרמינל השרת, מתוך wall_study, חלצו את ההגדרות; הפקודה מחליפה קבצי הגדרות באותם שמות:
    python -m zipfile -e wall_search_configs.zip .
    

    2. 

  2. בדקו את הניסוי הבסיסי. מתוך wall_study, באותה סביבת Python:

    prmkit check experiment.yaml
    

    check טוען את הרובוט והסביבה ובודק את ההתחלה והיעד הבסיסיים. הוא אינו בונה PRM ואינו בודק מראש את כל הסביבות בחיפוש.
    3. 

  3. הריצו את החיפוש. בחרו שם חדש לתיקיית התוצאות, ואז העתיקו את הפקודה:


    

    שינוי הקירות←דגימת PRM←בדיקות התנגשות←עלויות קשתות←חיפוש מסלולים←דירוג הסביבה
    

    אין צורך להריץ prmkit run בנפרד לכל סביבה: sweep מפעיל את התהליך עבור המועמדים. הקבצים המקוריים נשארים בסיס; כל ניסוי נכתב כעותק בתיקיית התוצאות.
    



הריצה נקטעה / שיניתי הגדרות / לא נמצא מסלול

לאחר הפסקה, בלי לשנות אף קובץ קלט, ממשיכים באמצעות:


לאחר שינוי קירות, טווחים, N/K, אפסילון או מטריקות — בחרו שם ריצה חדש. כפתור הורדה אינו מעדכן קבצים שכבר שמרתם: הורידו וחלצו שוב את ההגדרות העדכניות.


invalid_query: ההתחלה או היעד אינם תקפים במועמד הזה. no_path_in_roadmap: לא נמצא מסלול בגרף שנבנה; זו אינה הוכחה שאין מסלול במרחב הרציף. אפשר להגדיל N/K או לשנות את המשימה. failed או חיפוש חלקי דורשים קריאת השגיאה/סטטוס לפני פירוש הדירוג.








שלב 6 מתוך 6
קוראים את תוצאות החיפוש


פתחו תחילה:  — סיכום כל הסביבות והדירוג ביניהן.


    

  1. בדקו complete, את הסטטוס בכל שורה ב־rows ואת מספר המועמדים ב־evaluated. ב־Grid, grid_exhausted אומר אם כל הצירופים נסרקו.

    3. 

  3. למועמד שבחרתם, פתחו candidate_XXXXX.yaml כדי לראות את הסביבה והניסוי בפועל, ואת candidate_XXXXX/report.html כדי לראות מסלולים ועלויות. אין צורך ב־Isaac לצפייה בדוח.
    4. 



אפשר לטעון לכאן את הסיכום ולקבל את הנתיבים המדויקים

בחרו את space_summary.json שנוצר אצלכם. הקריאה מקומית בדפדפן, ואין העלאה לשרת. אם ההרצה בשרת, הורידו קודם את הקובץ למחשב שבו פתחתם מדריך זה.



טרם נטענו תוצאות. לא מוצגות כאן תוצאות מדומות.









בדפדפן פתחו את קובץ הדוח הבא:
