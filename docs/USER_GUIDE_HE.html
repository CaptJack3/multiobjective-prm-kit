מה רוצים לבדוק היום?

בחרו תרחיש וקבלו רצף קצר: מה להכין, איזה קובץ לערוך, מה להריץ ומה לקרוא בתוצאה. הפקודות מופעלות בטרמינל; המדריך מציג ומוריד הגדרות, ואינו מפעיל ניסויים בעצמו.

פעם ראשונה? התקנה ויצירת פרויקט

חלצו את חבילת המשתמשים ופתחו טרמינל בתיקייה שמכילה pyproject.toml. מסלול הרובוט נבדק ב־Linux; ב־Windows השתמשו בסביבת Linux/WSL.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[robot,usd]'
prmkit init my_study --template isaac

מכאן והלאה הריצו את הפקודות מאותה תיקייה, עם סביבת Python פעילה. הפרויקט נוצר ב־my_study/. אם הוא כבר קיים, אין צורך להריץ שוב init.

התבנית יוצרת UR5e ללא אביזרים, משימת דוגמה ו־N=24, K=6. היא אינה מייבאת את הסביבה אוטומטית. לבדיקת ההתקנה אפשר להשתמש בדוגמת הקירות להורדה בתרחיש הראשון או ב־my_study/scene.usda בתרחיש Isaac.

experiment.yamlהרובוט, המשימה, N/K והעלויות
scene.json / walls.jsonהמכשולים והמיקום ההתחלתי שלהם
space_*.yamlמה משנים בחיפוש ואיך מדרגים

בחרו את התרחיש שלכם

בכל תרחישי החיפוש מייבאים את הסביבה פעם אחת. המערכת משנה עותק של הגדרותיה ומריצה את התהליך לכל מועמד תקף.

הגדרות משותפות — רק כשצריך

איך מזהים את הקיר ואת השדה שצריך לשנות?

בקובץ הסביבה פתחו את רשימת objects ומצאו את הקיר לפי name. הספירה מתחילה ב־0. בדוגמת walls.json: קיר A הוא 0, קיר B הוא 1 וקיר C הוא 2.

בסצנה מיובאת, רצפה או מכשול נוסף עשויים לשנות את המספור. קיר עשוי גם להיות מורכב מכמה רשתות נפרדות. אין זיהוי אוטומטי של ״כל החלקים של קיר״ — צריך לשנות את העצמים המתאימים יחד.
שדה לדוגמהמשמעות
environment.objects.0.position_m.0מיקום X של מרכז עצם 0, במטרים במסגרת התכנון.
environment.objects.0.position_m.1מיקום Y; הסיומת 2 היא Z.
environment.objects.0.dimensions_m.0מידת X המקומית של קופסה; בדוגמה זו — עובי קיר A.
environment.objects.0.dimensions_m.1מידת Y המקומית; בדוגמה זו — רוחב קיר A.
environment.objects.0.dimensions_m.2מידת Z המקומית; בקיר הזקוף שלנו — גובה.

אם shape: mesh, אין מידות קופסה לשנות. שינוי מיקום עדיין אפשרי. לשינוי גודל אפשר להוסיף לעצם scale: [1, 1, 1] ולחפש על רכיביו; ההגדלה מתבצעת סביב ראשית הרשת, ואינה מדידת ״רוחב קיר״ אוטומטית.

איפה מגדירים רובוט, התחלה/יעד, N/K ואפסילון?

פותחים my_study/experiment.yaml בעורך טקסט. משנים את הסעיפים הקיימים, בלי להוסיף אותם פעם נוספת.

סעיףמה להגדיר
robotURDF, מסגרת כלי, גבולות/משקלים ומדיניות התנגשות. התבנית כבר כוללת UR5e; אביזרים דורשים הגדרה מפורשת.
query.start / query.goalsמצבי מפרקים בסדר ה־URDF; רדיאנים למפרקים סיבוביים, לא XYZ. check מציג את סדר המפרקים.
environmentשם קובץ הסביבה, יחסית לקובץ הניסוי. לדוגמה: walls.json או imported/scene.json.
prm.n / prm.kמספר הדגימות ומספר השכנים המוצעים. לבדיקה ראשונה השאירו 24 ו־6; הגדילו לאחר שהכול פועל.
search.epsilon0 לחיפוש Exact; ערך חיובי לחיפוש מקורב. חל על הגרף שנבנה.

אפשר לשנות פרמטרים זמנית בהרצה יחידה:

prmkit run my_study/experiment.yaml --output my_study/run_n1000 \
  --set prm.n=1000 --set prm.k=24 --set search.epsilon=0.05

בחיפוש סביבות, קובץ הניסוי הבסיסי מגדיר את N/K והמדדים לכל המועמדים. שמרו אותם קבועים אם מטרת הניסוי היא לבודד את השפעת הקירות.

מה ההבדל בין עלות המסלול לבין דירוג הסביבה?

ב־experiment.yaml בוחרים מטריקות לכל מסלול. התבנית כוללת אורך EE ועלות קרבה למכשולים. לדוגמה, אפשר לשנות את סף הקרבה ואת צורת הקנס:

metrics:
  - name: ee_length
  - name: clearance
    threshold: 0.1
    power: 2
    scope: world

ב־space_*.yaml בוחרים איך להשוות בין הסביבות, אחרי שחושבו המסלולים:

רוצים להעדיףrank.byrank.direction
סביבה שבה נמצא מסלול קצר יותרbest.ee_lengthmin
סביבה שבה נמצאה עלות קרבה נמוכה יותרbest.clearancemin
יותר מסלולים שהוחזרו בחיפושpath_countmax

שם המטריקה חייב להתאים ל־name בניסוי. best הוא הערך הנמוך ביותר שנמצא בין המסלולים שהוחזרו, ולא הוכחת אופטימום בעולם הרציף. מספר מסלולים תלוי גם באפסילון ובגרף ואינו מדד אוטומטי לגיוון.

מדד נראות דורש גם camera עם מסגרת, מיקום, כיוון ומטרה. נוסחת עלות או דירוג חדשה לחלוטין דורשת תוסף Python; שינויים בפרמטרים המובנים אינם דורשים קוד.

מה מתקבל, איך ממשיכים אחרי עצירה ואיך בודקים תוצאה?
תוצר / פקודהלמה הוא משמש
report.htmlדוח לכל ניסוי שהגיע לכתיבת תוצאות: מסלולים, עלויות ותצוגת EE.
space_summary.jsonסיכום חיפוש הסביבות: דירוג, הגדרות וסטטוס לכל מועמד. אין כרגע דשבורד HTML מרכזי לסריקה.
paths.npz, front.csvהמסלולים ווקטורי העלויות.
prmkit inspect DIRECTORYבדיקת תקינות תוצרים והצגת סיכום של ניסוי יחיד.
prmkit validate-path CONFIG PATHSאימות מחדש של מסלול שנשמר.
prmkit export-usd CONFIG PATHS --output replay.usdaייצוא מסלול להמחשה קינמטית ב־Isaac, ללא בקר או סימולציה דינמית.

לחידוש, הריצו בדיוק את אותה פקודת run או sweep עם --resume. אחרי שינוי קלט, הגדרות או קוד, בחרו תיקיית תוצאות חדשה.

רק מועמדים שהסתיימו ונמצא בהם מסלול מדורגים. חיפוש חלקי, משימה לא תקפה או גרף ללא מסלול מופיעים עם סטטוס מתאים. היעדר מסלול בגרף אינו הוכחה שאין מסלול במרחב.
