איזה קובץ פותחים?

פותחים את run_experiment.py בתיקיית החבילה. משנים את CASE_ID ואת המילון SETTINGS. כל קובצי הסביבה, השאילתות וההגדרות נוצרים עבורכם.

  1. מחלצים את ארכיון המקור ומגיעים לתיקיית multiobjective-prm-kit-0.4.0.
  2. ב־Linux או WSL מתקינים פעם אחת, רצוי עם Python 3.11:
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[robot,render]'

בודקים את כמות ההרצות ואז מפעילים:

python run_experiment.py --plan
python run_experiment.py --output runs/my_walls

ברירת המחדל היא שני קירות, ארבע סביבות, שאילתה אחת, N=24, K=6 ושני אפסילונים: שמונה חיפושים. זו דוגמת התקנה קטנה.

נבחר במפורש profile="mounted_ur5e": האסמבלי הקפוא מהניסוי האחר, כולל TCP בגובה 165.9 מ״מ, המצלמה והתושבת. הגריפר פתוח וקבוע. הקריאה הישירה run_case() עדיין משתמשת בזרוע החשופה לצורכי תאימות, ולכן יש לציין את ה־profile.

חלופה נוחה לשיתוף הגדרות: prmkit run examples/01_single_wall.yaml. קובץ הניסוי המאוחד משתמש באותו מנוע. אין חובה לעבור ל־YAML.

מגדירים את מרחב הקירות

ב־run_experiment.py מחליפים את הגדרות המקרה. למשל, שלושה קירות עם בחירה בין רוחבים וגבהים:

CASE_ID = "wall_random"
SETTINGS = dict(
    profile="mounted_ur5e",
    wall_count=3, max_environments=12,
    grid_points=3, offset_range=(-0.2, 0.2),
    widths=[0.4, 0.6], heights=[0.7, 0.9],
    thicknesses=[0.08], yaw_offsets=[-15, 0, 15],
    n=[250, 1000], k=[8, 16], epsilons=[0, 0.05],
    num_queries=3, query_k=16, seed=7,
    constraints=dict(min_clearance_m=0.005,
                     clearance_mode="enforce_during_search"),
    verification=dict(enabled=True, backend="coal_mesh", scope="all",
                      min_clearance_m=0.005),
    selection=dict(only_verified=True, max_per_query=7),
    render=dict(enabled=False),
)

זה כבר ניסוי של 288 חיפושים: 12 סביבות × 3 שאילתות × שני N × שני K × שני אפסילונים. התחילו בדוגמה הקטנה ובדקו --plan לפני ההפעלה.

CASE_IDמה קורה
wall_gridמכפלת הבחירות לכל קיר; max_environments מגביל לתחילת הרשימה.
wall_randomדגימה אקראית עם seed. אפשר טווחים כגון widths={"min":0.3,"max":0.9}.
wall_sobolדגימת Sobol של אותם פרמטרים, כולל טווחים רציפים.
fixed_environmentסביבה אחת מוגדרת או שמורה; מתאימה להשוואת צפיפויות PRM.
לכל קיר הגדרות שונות

מחליפים את wall_count ברשימת walls. שאר הפרמטרים נשארים ב־SETTINGS. המידות במטרים והזוויות כאן במעלות:

walls=[
    dict(center_xy=[1, 0], move_axis=[1, 0], offsets=[-0.2, 0, 0.2],
         widths=[0.4, 0.8], heights=[0.9], yaw_degs=[0, 15]),
    dict(center_xy=[0, 1], move_axis=[0, 1], offsets=[-0.1, 0.1],
         widths=[0.5], heights=[0.6, 1.0], yaw_degs=[90]),
]
בנק השאילתות משותף להשוואות. קירות אינם מסוננים אוטומטית מחפיפה; סביבה יכולה להפוך שאילתה ללא אפשרית. דגימות Random/Sobol עשויות לחזור על צירופים בדידים. אין עדיין חיפוש מודרך או טווח משתנה של מספר הקירות בתוך מקרה יחיד.

ליצירת סביבות ותצוגות XY בלי בניית גרף: prmkit generate examples/03_multi_wall_random.yaml --output runs/scene_bank.

משנים N/K לסביבה מסוימת

מעתיקים את הנתיב לסביבה שנוצרה ושומרים גם את השאילתות המקוריות. זה משווה את אותה משימה בצפיפויות שונות:

CASE_ID = "fixed_environment"
SETTINGS = dict(
    profile="mounted_ur5e",
    environment="runs/my_walls/environments/env_00000/scene.json",
    queries="runs/my_walls/queries.json",
    n=[1000, 5000], k=[16, 32], epsilons=[0, 0.05], query_k=32,
    constraints=dict(min_clearance_m=0.005,
                     clearance_mode="enforce_during_search"),
    verification=dict(enabled=True, backend="coal_mesh"),
    selection=dict(only_verified=True),
)

מפעילים עם תיקיית פלט חדשה: python run_experiment.py --output runs/denser_one. עבור כל הסביבות במחקר קיים אפשר להשתמש ב־prmkit rerun runs/my_walls --output runs/denser_all --n 1000 --k 16; אחריו מפעילים אימות עצמאי לפי הסף הרצוי.

ואם הסביבה נבנתה ב־Isaac Sim?

  1. שומרים USD מקומי עם קובצי ההפניות והנכסים שלו; עדיף סביבה סטטית.
  2. מתקינים את תוסף הייבוא וממירים לקובץ הסביבה של החבילה:
python -m pip install -e '.[usd]'
prmkit import-usd my_scene.usd --output imported/scene \
  --exclude /World/Robot

יש להתאים את --exclude לנתיב הרובוט האמיתי בסצנה. אם בסיס הרובוט אינו בראשית, מוסיפים --robot-frame /World/Robot/base_link עם ה־prim המתאים. בודקים את דוח הייבוא.

  1. מציבים environment="imported/scene/scene.json" בהגדרות ומגדירים שאילתות, מטרת מצלמה ורובוט מתאים.
  2. מפעילים כרגיל: ה־PRM, המרחקים והעלויות מחושבים ב־CPU עם Pinocchio/COAL; Isaac אינו נדרש להרצתם.
הייבוא מעביר גאומטריה סטטית נתמכת, לא סימולציית PhysX שלמה. רובוט מגיע בנפרד מ־URDF. צורות/קירובים לא נתמכים דורשים טיפול מפורש; לא מובטחת זהות לבדיקות המגע של Isaac. להעברת הסביבה לחוקר אחר יש להעביר את תיקיית הייבוא כולה עם הרשתות.

בודקים את המועמדים ובוחרים מסלולים

אילוץ בזמן החיפוש

enforce_during_search קובע מרווח קשיח ב־PRM. שינויו דורש בנייה ובדיקת גרף בהתאם למרווח החדש.

בדיקה אחרי החיפוש

postcheck_only בודק מסלולים שכבר נמצאו. הוא יכול לפסול מסלול, אך אינו מגלה מעצמו חלופה חדשה.

לדוגמה, לבדיקת Mesh מחודשת בסף של 2 ס״מ, בלי להריץ שוב את ה־Solver:

prmkit verify runs/my_walls --backend coal_mesh --scope all \
  --min-clearance-m 0.02 --max-joint-step-deg 0.5
prmkit explore runs/my_walls

פותחים runs/my_walls/explorer/explore.html. בוחרים קבוצה, מסננים לפי אימות/עלות/מרווח, ולוחצים על נקודות או תיבות בטבלה. הבחירה מקושרת בין שלוש ההקרנות. מורידים selected_paths.json ומעבירים אותו למחשב שמריץ את החבילה.

לבחירה אוטומטית של קצוות, פתרון מאוזן ופשרות זוגיות מתוך המועמדים שעברו בדיקה:

prmkit select runs/my_walls --output selected_paths.json
סטטוסמשמעות
discrete_verifiedכל הדגימות שנבדקו עברו; זו אינה הוכחת בטיחות רציפה או פיזית.
collision_foundנמצאה התנגשות או נגיעה בדגימה.
clearance_violationהמרווח שנמדד קטן מהנדרש.
validation_errorשגיאת בדיקה, שינוי נכסים או חריגה מתקציב; לעולם אינה נחשבת מעבר.
unverifiedהמסלול לא נכלל בבדיקה.
Verified candidate PF מחושב רק מתוך המועמדים שעברו. הוא אינו חזית גלובלית מוכחת. בדיקת 2 ס״מ עלולה לפסול אפילו את תנוחת ההתחלה בשל מרווח עצמי. התוצאות המקוריות והעלויות שלהן נשמרות.

אף אחת מהפקודות האלה אינה מפעילה חיפוש מחדש. הרינדור יוצר MP4 של תנועת הרובוט והגאומטריה ב־CPU. ה־USD כולל את המכלול המעודכן ומצלמת שורש כף היד, לפתיחה ב־Isaac.

קובץ / תיקייה במחקרמה מקבלים

runs/run_XXXXXXX/גרף, עלויות, מסלולי מועמדים והגדרות פתורות.

הסרטון הוא המחשה גאומטרית עם זמן תצוגה, לא מסלול ביצוע עם מגבלות מהירות/תאוצה. אין כאן סגירת גריפר, סימולציית אחיזה או רינדור RTX אוטומטי. קובץ בחירה קשור לקטלוג המסוים שממנו נוצר.

שינוי אפסילון יכול להשתמש באותו גרף ובאותן עלויות. שינוי N/K, סביבה, שאילתה או אילוץ קשיח בונה גרף מחדש. באותה מערכת קבצים הגרפים המשותפים מקושרים ב־hardlink; אין לערוך אותם ידנית.

מה השתנה בארכיטקטורה?

הליבה הקיימת נשמרה. נוספו שכבות מסביב לה, כולן בתוך user_distribution/. קוד המחקר והתוצאות ההיסטוריות נשארו במקומם.

שלוש העלויות בתצורה החדשה

  • O1 — אורך TCP: תנועת נקודת הכלי במטרים, כולל היסט הגריפר.
  • O2 — חשיפה לקרבה: אינטגרל של קנס מרחק מהסביבה; סף ברירת מחדל 10 ס״מ וחזקה 2. אינו המרווח המינימלי.
  • O3 — אובדן נראות: אינטגרל של החלק הלא נראה במטרה, לפי 64 קרניים, שדה ראייה וחסימות גאומטריות.

O2/O3 משוקללים לאורך תנועת המפרקים. האורך המפרקי הוא מידת אינטגרציה ומרחק בגרף; הוא אינו מטרה רביעית אוטומטית. את metrics ואת camera אפשר לשנות ב־SETTINGS; נוסחה חדשה נכתבת כתוסף מטריקה. יש להגדיר מטרת צילום מתאימה לסביבה — ברירת המחדל היא מטרה וירטואלית קטנה לדוגמה.

מה עדיין לא ממומש?
  • חיפוש סביבות מודרך, אילוצי XYZ כלליים, replan אוטומטי אחרי פסילות ועיבוי אינקרמנטלי של PRM.
  • גרף בסיס משותף לכל השאילתות/הסביבות; כיום השיתוף הוא בין אפסילונים בעלי אותם קלטי גרף.
  • סגירה דינמית של הגריפר, כיול מצלמה פיזי, תצוגת רובוט 3D בתוך ה־Explorer, לַאסוֹ וייצוא מערך VLA מלא.
  • זהות מספרית לניסוי 5M ההיסטורי או אישור ביצועים בקנה המידה הזה. כאן נבדקו ניסויים קטנים.
החבילה עצמאית; תוצאות ריצה שומרות גם נתיבי נכסים פתורים. כדי לבצע אימות מחדש במחשב אחר צריך לשחזר/להתאים את נתיבי הנכסים. ה־Explorer עצמו, המדריך הזה וייצוא המסלולים אינם דורשים את תיקיית המחקר המקורית.

לפרטים נוספים בתוך הארכיון: docs/WORKFLOW.md, docs/OBJECTIVES.md, docs/VERIFICATION_AND_CLEARANCE.md, docs/SPEC_ALIGNMENT_20261123.md ו־VALIDATION.md.
